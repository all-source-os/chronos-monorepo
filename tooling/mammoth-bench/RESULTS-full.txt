Honesty note: the precision edge over the grep baseline NARROWED from +0.17
(18-memory smoke set, bench.py) to +0.07 at 60 memories — expected, as a denser
corpus gives the keyword baseline more overlap to exploit. Memory still wins on
hit@3/hit@5/MRR, latency stays sub-4ms, durability holds. Per the proposal's
honesty rule, the softening is published, not hidden; the improvement levers
(hybrid keyword+vector, graph depth>0, larger embedder) remain unused here =
headroom.

Durability methodology: this checks PERSISTENCE (node count via prime_stats
after closing and reopening the server on the same data dir), NOT recall ranking.
An earlier version wrongly tested whether each gold still ranked top-5 after
restart and reported a spurious "FAIL (9/10)"; ranking can miss a slot without
any data loss, so node-count is the correct survival signal.
